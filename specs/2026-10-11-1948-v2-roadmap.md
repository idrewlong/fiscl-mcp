Supersedes: none

## Goal
Take fiscl from "what happened" to "what should I do next" (net worth, goals, debt payoff, "can I afford X?", anomaly and subscription alerts), let users fix their data from chat (splits, notes, tags, budgets, dismissals), and make the tax output preparer-ready. All of this stays local, deterministic, and read-only to the outside world.

## Non-goals (all phases)
- Moving money or writing to any institution. Advice. A web UI. Double-entry accounting.
- Network calls outside the bank-connector layer (Phase 2) and QuickBooks (Phase 4). Each connector needs its own decision entry.

## Phase 1: edit, plan, monitor

### Context
- Services follow `fn(conn, cfg, **args) -> dict` with `today=None`, return `meta`, and use `common` helpers. Writes use `dry_run=True` + `common.plan_result`. See `AGENTS.md` Conventions.
- Patterns to copy: `analysis/edits.py` (dry-run write), `analysis/forecast.py` (projection + assumptions), `analysis/spending.py` (grouped SQL with `TXN_FROM` + `txn_filter`), `tests/test_analysis.py` (pinned `TODAY`, `add_txn`).
- `recurring_dismissed` already exists in the schema, and `recurring.refresh_recurring` already honors it. Only the tool is missing.

### Data: migration 3 (append to `db.MIGRATIONS`; a backup runs automatically first)
```sql
CREATE TABLE tags (
  transaction_id INTEGER NOT NULL REFERENCES transactions(id) ON DELETE CASCADE,
  tag TEXT NOT NULL,                              -- cleaned, lowercased, ≤ 40 chars
  PRIMARY KEY (transaction_id, tag));
CREATE INDEX ix_tags_tag ON tags(tag);

CREATE TABLE splits (                             -- children of one parent transaction
  id INTEGER PRIMARY KEY,
  transaction_id INTEGER NOT NULL REFERENCES transactions(id) ON DELETE CASCADE,
  amount INTEGER NOT NULL,                        -- minor units, same sign as parent
  category_id INTEGER REFERENCES categories(id),
  scope TEXT CHECK (scope IN ('personal','business')),
  note TEXT);
CREATE INDEX ix_splits_txn ON splits(transaction_id);

CREATE TABLE manual_assets (                      -- house, vehicles, gear, loans held elsewhere
  id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE,
  kind TEXT NOT NULL CHECK (kind IN ('property','vehicle','equipment','investment','cash','liability','other')),
  value INTEGER NOT NULL,                         -- minor; liabilities stored positive, subtracted
  as_of TEXT NOT NULL, note TEXT);

CREATE TABLE goals (
  id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE,
  target INTEGER NOT NULL CHECK (target > 0), target_date TEXT,
  account_id INTEGER REFERENCES accounts(id),     -- track an account's balance, or
  saved INTEGER NOT NULL DEFAULT 0,               -- a manual running amount
  created_at TEXT NOT NULL, archived INTEGER NOT NULL DEFAULT 0);
```
- `transactions.note` already exists.
- **Split semantics (the risky part):** a parent with splits is replaced by its children in every aggregate. Implement this once as a SQL view, `txn_lines`, that UNIONs unsplit transactions with split children (the parent's date, account, transfer_group, and pending flag; the child's amount, category, and scope). Then switch `TXN_FROM` to `txn_lines t JOIN accounts a … LEFT JOIN categories c …`. Aggregates pick splits up automatically. Row listings (`query_transactions`) keep showing parents, with a `splits` array. Validation: children must sum exactly to the parent amount, and you can't split transfers.
- Rollback: no down-migrations exist (forward-only, pre-migration backup). Document restoring from `backups/`.

### Risks & open questions
- **Split view performance**: the UNION view on every aggregate. → Mitigation: index `splits(transaction_id)`, benchmark the demo plus a 50k-row fixture; aggregate queries must stay under 200 ms.
- **`set_budget` rewriting a hand-edited TOML loses comments.** → Recommended: rewrite only the `[[budget]]` blocks and keep the header comments, with a `.bak` always. Needs human decision? No.
- **Debt APRs aren't in bank exports.** → Recommended: require them as args, plus an optional `[debts]` table in `config.toml` so users enter them once. Needs human decision? No.
- **Anomaly thresholds produce noise.** → Recommended: conservative `normal` defaults (spike ≥ 2.5× median and ≥ $50; new merchant ≥ $200), and every finding phrased as a question. Tune on demo data.
- **State tax depth (Phase 3).** → Recommended: due dates plus a user-supplied flat planning rate, mirroring the federal `income_tax_rate_pct`. Computing real state liability (brackets, local taxes, residency across 50 jurisdictions) is out of scope: it needs yearly upkeep and drifts into advice. Needs human decision? Confirmed direction 2026-10-11, pending sign-off.
- **Multiple businesses (Phase 3) changes the scope model.** → Phase 1 must not hard-code a single business. Keep `scope` values as they are; Phase 3 adds a nullable `business_id`. Needs human decision? Yes, before Phase 3.

## Phase 2: read-only bank connections (Plaid, Teller)

### Goal
Let users connect their banks through Plaid or Teller (in addition to SimpleFIN and file imports), with a guarantee enforced in code and tests that fiscl can only **read** balances and transactions.

### Read-only is enforced in four layers
1. **What we ask for.** Plaid Link tokens are created with `products: ["transactions"]` only (`PLAID_PRODUCTS` constant). We never request `auth` (account/routing numbers), `transfer`, `payment_initiation`, `identity`, `signal`, `income`, or `investments_auth`. Teller Connect uses `products: ["transactions", "balance"]` and never `payments`. Both providers enforce the granted products on their side.
2. **What the client can call.** Each connector has a hard-coded endpoint allowlist, and the HTTP helper refuses anything else before a socket opens:
   - Plaid: `/link/token/create`, `/item/public_token/exchange`, `/transactions/sync`, `/accounts/get`, `/item/remove`
   - Teller: `GET /accounts`, `GET /accounts/{id}/transactions`, `GET /accounts/{id}/balances`, `DELETE /accounts/{id}`, `DELETE /accounts` (revoke the whole enrollment). Never `/accounts/{id}/details` (full account/routing numbers), `payments`, `verify*`, or `identity`
   - Plaid test-only: `/sandbox/public_token/create`, allowed only when environment = sandbox

   Any other method or path raises `SyncError`.
3. **Where it can go.** https only. Host allowlists: `production.plaid.com`, `sandbox.plaid.com` (dev only), and `api.teller.io`. No redirects are followed and credentials go in unredirected headers, using the same `open_url` as SimpleFIN. TLS is verified. Teller's mTLS client certificate lives in the keychain. Python's `ssl` can only load certs from file paths (research: the `/dev/fd` trick fails on macOS), so the cert and key are written as one PEM into a `mkdtemp` (0700) folder, loaded into a reusable `SSLContext`, then unlinked and the folder removed in `finally`. `os.memfd_create` is used where available (Linux). The file exists only for milliseconds, is private to the user, and is never in the data dir.
4. **What exists in the code.** No transfer, payment, or processor code paths. A test scans `src/` for forbidden endpoint strings (`/transfer`, `/payment_initiation`, `/processor`, `/bank_transfer`, `/payments`) and fails if any appear.

### Design
- **Shared connector layer** in `sync/`: `sync/base.py` (allowlisted `open_url`, keychain helpers, the `Connector` protocol: `setup()`, `fetch(start, end) -> list[ParsedStatement]`, `forget()`); `sync/plaid.py`; `sync/teller.py`; `sync/simplefin.py` refactored onto the base. Everything feeds the existing `import_statements`, so dedupe, transfers, rules, and recurring detection all work unchanged.
- **Connecting a bank is human-only, via the CLI**: `fiscl connect plaid|teller`. It is never an MCP tool, so the model can't start a connection.
  - It starts a one-shot server on `127.0.0.1` at a random port with a random 32-byte path token.
  - It opens the browser to a local page that loads the provider's official Link/Connect script (the only third-party script involved; it runs in the user's browser, not in fiscl).
  - The page posts the public token back to that local URL. fiscl exchanges it, stores the access token in the OS keychain, and shuts the server down. The server accepts one request and times out after 10 minutes.
- **Environments:** `[connectors.teller] environment = "development"` (default; free tier with real banks, 100 enrollments per Teller account for its lifetime, mTLS required) or `"sandbox"` (test data, no cert). Teller `production` needs business verification (KYB) and is out of reach for individuals. Plaid: `sandbox` or `production` (Trial = 10 Items free, or Pay-as-you-go). There is no Plaid "development" host. The Teller `balance` endpoint is billed per call in production, so call it once per sync at most.
- **Sign conventions:** Plaid `amount` is positive for money out, so invert it to fiscl's negative-is-out. Teller's sign convention is **not documented**: the parser takes it from a recorded sandbox fixture for depository and credit accounts, and a human must verify it against a live sandbox enrollment before release.
- **Bring your own keys.** Users create their own Plaid or Teller developer account. `client_id`/`secret` (Plaid) and the certificate/key (Teller) are entered with hidden input and stored only in the keychain. The keychain is required: no keychain, no connector, same rule as SimpleFIN today.
- **MCP surface:** `sync_accounts` gains `provider: simplefin | plaid | teller | all` (default `all` connected). It stays `openWorldHint=true`, read-only toward the bank, and writes only the local DB. A new read tool, `list_connections`, returns provider, institution, accounts, last sync, and status (no tokens). Disconnecting is CLI-only (`fiscl connect forget plaid`), and it calls `/item/remove` so the provider revokes access.
- **Account numbers:** only the provider's account id (hashed into `acct_hash`) and the mask/last4. Never full numbers (we never request `auth`).
- **No webhooks**, which would need a public endpoint. Polling happens through `sync_accounts` and `fiscl sync run`.

### Data
- Migration: `connections` table (`id, provider, institution, item_ref_hash, created_at, last_sync_at, status`). Tokens are **not** stored in the DB; the keychain entry is keyed by `fiscl:<provider>:<item_ref_hash>`.

- [x] The link-token request body contains exactly `products: ["transactions"]` (unit test against the built payload); Teller requests contain no `payments`
- [x] Calling a non-allowlisted path or host (e.g. `/transfer/create`, `http://`, or another host) raises before any socket opens (test with sockets blocked)
- [x] A 302 from the provider raises `SyncError` and the credentials header is unredirected (same tests as SimpleFIN)
- [x] The source-scan test for forbidden endpoint strings passes

- [x] The Teller flow passes against recorded fixtures (accounts, paginated transactions with `from_id`, balances, `DELETE /accounts`); the cert temp file is gone after context creation (test)

- [x] SECURITY.md and README document the data flow: the aggregator holds the bank connection and sees the data in transit; fiscl stores it only locally

### Risks & open questions
- **The aggregator sees your data.** Plaid and Teller are third parties with their own retention policies, unlike file imports. → Document it plainly, keep file import as the zero-third-party option, and show the provider on every synced account. Needs human decision? No.
- **Primary provider: superseded 2026-10-11 (later the same day).** Teller has no public signup. New order: free file import, then SimpleFIN ($1.50/mo), then Plaid Trial, then Teller for existing customers (see DECISIONS.md). Original note: **decided → Teller** is the recommended, documented-first connector (`fiscl connect teller`). Plaid and SimpleFIN are fully supported alternatives the user can pick; `sync_accounts` syncs every connected provider. Plaid is tested against its sandbox; production needs the user's own approved Plaid app.
- **The Link page loads a third-party script.** → It runs only on the one-shot localhost page, with a per-provider CSP. Plaid's documented CSP needs `script-src`/`frame-src`/`connect-src` for `cdn.plaid.com` and `*.plaid.com`. Teller's hosts (`cdn.teller.io` plus undocumented Connect hosts) must be recorded from a real sandbox run. If Connect rejects plain `http://127.0.0.1`, the fallback is a self-signed local https cert on the one-shot server. Never inside the MCP server or chart view.
