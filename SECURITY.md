# Security

fiscl handles financial data, so its defaults are conservative and its guarantees are enforced in code and covered by tests (`tests/test_guardrails.py`, `tests/test_security.py`, `tests/test_mcp.py`, `tests/test_simplefin.py`, `tests/test_connectors.py`, `tests/test_teller.py`, `tests/test_plaid.py`).

## Where your data goes

| Data path | Where it goes | Notes |
|---|---|---|
| Bank exports you import (CSV/OFX/QFX) | Your machine only | Parsed locally into `~/fiscl/fiscl.db`. No third party involved. |
| Optional bank sync (SimpleFIN, Plaid, Teller; Plaid and Teller are beta) | Bank → aggregator → your machine | The aggregator holds the bank connection and sees the data in transit, under its own privacy policy. fiscl stores it only locally. Sync is read-only and opt-in. |
| Optional QuickBooks Online read (sandbox only for now) | Intuit → your machine | Read-only; fiscl copies invoices and profit-and-loss totals into the local database. Invoice customer names and document numbers are returned by `receivables` and go to your AI model unless `redact_descriptions = true`, which withholds them (and the customer filter) while keeping amounts and dates. |
| **Tool results sent to your AI model** | **Your MCP client sends them to whatever model it uses** | fiscl runs locally, but when you ask Claude (or another assistant) a question, the numbers and merchant names fiscl returns go to that model's provider, just like anything else you type into the chat. To limit what leaves your machine: keep aggregates by default (fiscl does), set `redact_descriptions = true`, or use an MCP client backed by a local model. `redact_descriptions` hides raw descriptions and memos only; normalized merchant names are still returned, and for P2P payments (Zelle, Venmo, and similar) those can include the counterparty's name. |
| Dependencies | Resolved when you install | `pip` and `uvx` installs resolve dependency version ranges at install time. For exactly the versions this project tests, install from a clone with `uv sync` (uses `uv.lock`). |
| Proxies | `HTTPS_PROXY` and similar | A proxy sees only TLS-encrypted traffic (hostnames and sizes) unless you configured a trusted TLS-inspecting proxy, in which case it can read sync traffic. |

fiscl itself has no telemetry, no analytics, no accounts, and no servers.

## Guarantees

- **It never moves money.** There is no code path for payments, transfers, or trades. Every bank integration is read-only by protocol, and the schema has no payee or destination concept.
- **Local only.** Data lives in `~/fiscl` (or `$FISCL_HOME`/`--home`). The core makes no network calls; a test blocks sockets and calls every registered MCP tool except `sync_accounts` through an in-process client (a new tool fails the test until it is added). Only the sync code may connect, over https to allowlisted hosts.
- **Private files.** The data directory is 0700, and fiscl runs with umask 077, so everything it creates (database, WAL, logs, backups, `.bak` files) is 0600. `fiscl doctor` checks and repairs permissions, warns when the data directory is inside a cloud-synced folder (iCloud Drive, including `~/Desktop` and `~/Documents` when iCloud Desktop & Documents is on, Dropbox, OneDrive, Google Drive, Box; every command prints this warning to stderr), repairs permissions on `.bak` files, the install key, processed/failed inbox files, the demo folder, and profiles, and warns when FileVault is off on macOS. fiscl refuses to use your home directory itself as its data directory.
- **Encryption at rest** relies on OS full-disk encryption (FileVault, BitLocker, LUKS). Turn it on. An encrypted database (SQLCipher) is on the roadmap.
- **Secrets.** Bank-sync credentials are stored only in your OS keychain. fiscl refuses to sync if no keychain is available rather than fall back to plain text. "Available" means an allowlisted OS backend, checked by exact class: `keyring.backends.macOS.Keyring` (macOS Keychain), `keyring.backends.Windows.WinVaultKeyring` (Windows Credential Locker), `keyring.backends.SecretService.Keyring` and `keyring.backends.libsecret.Keyring` (GNOME Keyring / KeePassXC and other Secret Service providers), and `keyring.backends.kwallet.DBusKeyring` / `keyring.backends.kwallet.DBusKeyringKWallet4` (KDE Wallet). Every member of a chained keyring must be on the list. Anything else is refused, including the plaintext or encrypted-file backends from `keyrings.alt` (common on headless Linux), the null backend, and any backend selected through `PYTHON_KEYRING_BACKEND` or `keyringrc.cfg`. SimpleFIN uses the same check. Deleting a credential surfaces keychain errors instead of pretending it was removed. Setup tokens are read with hidden input, never from command-line arguments. Credentials travel in an `Authorization` header, never a URL, and that header is never forwarded on redirects.
- **Network hardening for sync.** https only, an allowlist of hosts, TLS verification on, and redirects never followed, so credentials can't be bounced to another host. Each connector also has a hard-coded allowlist of (method, path) pairs checked before any socket opens: Teller may only read accounts, transactions, and balances, and revoke access (`DELETE`); Plaid may only call `/link/token/create`, `/item/public_token/exchange`, `/transactions/sync`, `/accounts/get`, and `/item/remove` on the one host of your configured environment (`sandbox.plaid.com` or `production.plaid.com`), and its Link token requests only the `transactions` product. Nothing can reach account/routing numbers, identity, verification, or money movement, and tests pin the exact route lists and scan every string constant in `src/` for those endpoint strings, and an AST test checks that only `sync/base.py` imports network libraries (the loopback connect server in `sync/connect.py` is the one named exception), that `Policy` is only constructed in the connector modules, and that every request passes a connector policy.
- **Bank connections are human-only.** `fiscl connect plaid|teller` runs a one-shot server on 127.0.0.1 (random port, random 32-byte URL token, one POST, 10-minute timeout that stalled connections can't extend, strict CSP; the terminal prints the institution it saved so you can confirm it, and a failed save restores any previous token and revokes the new grant at the provider) that hosts the provider's own Connect/Link widget in your browser (the only third-party script involved, allowed by a per-provider CSP: Plaid's needs `cdn.plaid.com` and `*.plaid.com`); it is never an MCP tool, so a model can't start one. Access tokens, your Plaid client_id/secret, your Teller certificate/key, and application id live only in the OS keychain (`fiscl:<provider>:<ref>`); the database stores only provider, institution, a hashed reference, sync status, and Plaid's opaque sync cursor (a bookmark, not a credential). `fiscl connect teller|plaid --reconnect` re-authorizes an expired connection through the same enrollment/Item (Teller `enrollmentId`, Plaid Link update mode) so no duplicate accounts appear. `fiscl connect forget teller|plaid` revokes access at the provider (`DELETE /accounts`, `/item/remove`) and deletes the keychain entries. Plaid Link on plain `http://127.0.0.1` is only verified for the sandbox; production Link from that origin must be confirmed by the user.
- **Client certificate on disk, briefly.** Python's `ssl` can only load a client certificate from a file path. On Linux fiscl uses an in-memory file; elsewhere it writes the PEM (0600) into a fresh private (0700) temp directory, loads it, and deletes both immediately. It exists for milliseconds and is never in the data directory.
- **Redaction.** Full account numbers are never stored, only a keyed hash (HMAC-SHA256 under a random 32-byte per-install key, kept in the OS keychain or, without one, a 0600 `.install_key` file that is never copied into backups) and the last 4 digits, so the hash cannot be brute-forced from the database alone. Without an OS keychain (the default install, without `fiscl[sync]`) the key lives in `~/fiscl/.install_key`, so a copy of the whole data folder (Time Machine, a synced folder) carries both the key and the database. Older database backups keep their pre-upgrade legacy (unkeyed) hashes, and accounts that were never re-imported stay unkeyed; run `fiscl doctor` and re-import to upgrade them. Imports and syncs refuse to run (`key_missing`) when the database's recorded key fingerprint doesn't match the key on this machine, instead of creating duplicate accounts. Residual: raw bank descriptions can themselves contain account numbers; they are returned only after redaction, and `redact_descriptions = true` withholds them entirely. Older unkeyed hashes are upgraded in place on the next import. Every tool response is scrubbed for card numbers (Luhn-checked), SSNs, and long account-like numbers.
- **Untrusted text.** Bank descriptions are Unicode-normalized, stripped of control and bidi characters, capped, and returned only as labeled data. The server tells the model never to follow instructions found in them.
- **Chart view.** The in-chat chart has a strict Content-Security-Policy (no network, no external resources), renders bank-derived labels as text only, and accepts messages only from its host frame.
- **Deliberate writes.** Category, scope, tag, note, split, budget, asset, goal, recurring, and mileage edits default to a dry run and bulk edits are capped; imports are atomic. `dry_run` is a safety default, **not a gate**: a model can pass `dry_run=false`. The human gate is your MCP client's tool approval, so keep per-call approval on for fiscl's write tools. Tools that can remove or overwrite your data (`apply_categories`, `add_note`, `tag_transactions`, `split_transaction`, `dismiss_recurring`, `set_budget`, `manage_asset`, `manage_goal`, `set_scope`, `record_1099`, `manage_business`) are annotated `destructiveHint=true` so clients can prompt accordingly; `log_trip` only appends and is not. `sync_accounts` writes to the database with no dry run and makes network calls to your aggregator, which can be billed per call by the provider. The database is backed up before migrations and daily (last 14 kept).
- **Install key portability.** Because account hashes depend on the per-install key, moving to a new machine or restoring a database backup without the key makes re-imports create duplicate accounts. `fiscl key export PATH` writes the key to a new owner-only file (hidden confirmation; the key is never printed or logged; it refuses cloud-synced folders and existing files) and `fiscl key import PATH` adopts it (it refuses to replace a different key that existing accounts use unless `--force`). Back the key up separately from database backups: anyone holding both the key and the database can test guesses against account hashes. A non-secret fingerprint (`sha256(key)[:16]`) is stored in the database, and `fiscl doctor` warns when it doesn't match the key on this machine.
- **Telemetry off.** `fiscl` sets `OTEL_SDK_DISABLED=true` before loading the MCP SDK so no OpenTelemetry export can carry tool traffic; a value you set yourself is respected.
- **Forgetting a connection** deletes the stored credentials and revokes access at Plaid and Teller. It does not delete transactions already synced into your database, nor backups. SimpleFIN forget is local only (it removes the keychain entry); revoke the access at the SimpleFIN Bridge as well. Teller certificate and key files you downloaded stay where you saved them after fiscl copies them into the keychain; the CLI reminds you to delete them.
- **Keychain scope.** On macOS the keychain items are readable by code running as you with the same interpreter, so this protects against other users and a stolen disk, not malware already running as you.
- **Audit trail.** `fiscl audit` shows every tool call with sanitized arguments; merchant names, descriptions, and amounts are never logged, and failed calls log only a stable error code (such as `not_found`), never the error text.

## HTTP transport (optional)

`fiscl serve --http` listens only on the literal loopback address `127.0.0.1` or `::1`; anything else is refused before a socket opens. Every request needs a bearer token kept in the OS keychain and read on each request, so `fiscl http token rotate` takes effect immediately. If the keychain can't be read, requests fail closed with 503. Requests with any `Origin` header are rejected (browser pages can't reach it), `Host` must match exactly including the port, and no CORS headers are ever sent. Twenty failed attempts in 60 seconds lock the server for 60 seconds. Access logs and the server header are off.

Over HTTP, only read-only tools are available unless you set `[http] allow_writes = true`; if you do, keep per-call approval on in your client. Residual risk: a process running as your user that binds the port first could collect the token from a client that connects to it. fiscl never picks a port for you, and you can rotate the token. Plain HTTP on loopback is by design; malware running as your user is out of scope.

## Notifications and digests

After applied edits, syncs and imports, fiscl tells your MCP client which resources changed (resource URIs only, no data). `write_digest` and `fiscl digest --write` save a weekly summary under `~/fiscl/digests/` (folder 0700, files 0600, no caller-chosen paths). Digests contain merchant names and amounts, scrubbed for card, SSN and long account-like numbers. `write_digest` isn't available in read-only HTTP mode.

## Exports

`export_schedule_c` writes files only under `~/fiscl/exports/` (folder 0700, files 0600, symlinks refused, no caller-chosen paths). Exports are as sensitive as the database: send them to your preparer over a secure channel and delete them when you're done. `fiscl doctor` checks the folder's permissions. Exports are scrubbed like tool responses: card numbers (Luhn-checked), SSNs, and long account-like numbers in text cells are masked in CSV and Markdown (so 9+ digit invoice numbers in notes are masked too); amounts are untouched. Files are published with a hard link so a name that appears at the last moment is never overwritten.

## QuickBooks Online (sandbox only, beta)

The QuickBooks connector is read-only in code: GET-only routes on Intuit's sandbox API host, plus POST only to the token and revoke endpoints. The query text must match a fixed `SELECT * FROM Invoice|Customer|Payment` shape, and the source scan rejects write endpoints. Intuit has no read-only OAuth scope, so the stored refresh token could write to your books if someone stole it from your keychain; fiscl's code cannot. Only the refresh token and company id are stored, both in the OS keychain; access tokens live in memory only. Production companies are refused until a human verifies Intuit's production process. `fiscl connect forget qbo` revokes at Intuit first and deletes the mirrored invoices.

Amazon order history is imported from the file you download. fiscl never logs in to Amazon.

## Holdings

Positions files are parsed locally. There are no price or FX lookups: prices come only from your imports, and exchange rates are only ones you type (`set_fx_rate`) or import (`fiscl fx import`). Full account numbers in broker files are never stored: the column is ignored by default, or cut to the last 4 digits only to choose the matching fiscl account.

## Tax records you enter

1099 forms you record (`record_1099`) are stored only in the local database. Nothing is fetched. Payer names and amounts never appear in error messages or the audit log.

## Recommendations for users

1. Turn on full-disk encryption.
2. Keep `~/fiscl` out of cloud-synced folders (`fiscl doctor` will tell you).
3. Don't enable fiscl in the same MCP client session as tools that can send data to the internet (web fetch, email, etc.) unless you trust every data source. Bank descriptions are untrusted text, and the safest assistant setup can't be tricked into sending your data anywhere.
4. Set `redact_descriptions = true` in `config.toml` if you don't want raw bank text sent to your AI model.

## Reporting a vulnerability

Open a private security advisory on the GitHub repository rather than a public issue.
